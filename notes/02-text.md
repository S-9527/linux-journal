# Phase 2 · 文本三剑客

> **grep 找、sed 改、awk 取列。**
> 本文所有输出均为实际执行所得。

---

## 分工

| 工具 | 定位 | 一句话 |
|---|---|---|
| `grep` | **筛选** | 哪些行/哪些部分要 |
| `sed` | **替换** | 把行里的字换掉 |
| `awk` | **取列 + 聚合** | 按列处理并算账 |

三者的边界经常模糊。判断标准：

- 只想**看**符合条件的行 → `grep`
- 想**改**行里的内容 → `sed`
- 需要**按列拆开并计算** → `awk`
- 需要**按列拆开并计算，且一行内多次判断** → `awk`（不要用多个 sed 拼）

## 1. grep 进阶

```bash
grep -i ERROR access.log          # 忽略大小写
grep -E "ERROR|WARN" access.log   # 正则（或关系）—— 实测命中 6 行
grep -c ERROR access.log          # 只输出行数 —— 5
grep -rn "TODO" .                 # 递归 + 行号
grep -o "192\.168\.[0-9]*\.[0-9]*" access.log   # 只输出匹配部分
grep -v "INFO" access.log         # 反选
```

### `-o` 的威力：把内容抠出来

```console
$ grep -o '192\.168\.1\.[0-9]*' access.log | wc -l
10                      # 出现总次数

$ grep -o '192\.168\.1\.[0-9]*' access.log | sort -u
192.168.1.10
192.168.1.11
192.168.1.12
192.168.1.13
192.168.1.14                        # 去重后 5 个
```

**`-o` + `sort -u` 是"提取集合"的标准套路。** 想从混杂文本里拿 ID、邮箱、URL，先用 `-o` 抠出来再处理。

⚠️ 正则里 `.` 要转义成 `\.`，否则 `1.1` 里的点会匹配任意字符。

### `-A` / `-B` 看上下文

排错时经常需要知道"错误前后发生了什么"：

```console
$ grep -A1 "10:00:03" access.log
2026-09-28 10:00:03 ERROR 192.168.1.11 GET /api/login 500 340ms
2026-09-28 10:00:05 INFO  192.168.1.10 GET /api/orders 200 8ms
```

`-A2` 后 2 行、`-B2` 前 2 行、`-C2` 前后各 2 行。

## 2. sed 替换

基本形式：`s/查找/替换/g`

```bash
sed 's/ERROR/ERR/g' access.log              # 只打印，不动文件（安全）
sed -i 's/ERROR/ERR/g' access.log           # 直接改文件
sed -i.bak 's/ERROR/ERR/g' access.log       # 改文件 + 留备份（推荐）
sed '/INFO/d' access.log                    # d = delete，删掉匹配行
```

**为什么 `-i.bak` 比 `-i` 好：** 批量替换一旦写错正则，原始数据就没了。留个 `.bak` 是给自己留后悔药。实测验证：

```console
$ sed -i.bak 's/ERROR/ERR/g' /tmp/w.txt
$ grep -c ERR /tmp/w.txt.bak
5                      # 备份里 ERROR 原样保留
```

**`sed -i` 的风险点：** 它的替换语法和正则高度重叠，误伤很难一眼看出来。养成习惯：**先不带 `-i` 跑一遍看输出，确认无误再加 `-i`**。

## 3. awk 取列

awk 的默认动作是"逐行处理"，`$N` 表示第 N 列（**默认按空白分隔**）。

```bash
awk '{print $4}' access.log            # 第 4 列（IP）
awk '{print $2, $7}' access.log        # 多列，空格分隔输出
awk -F',' '{print $1}' a.csv          # 自定义分隔符
awk '/ERROR/ {print $4}' access.log    # 只处理含 ERROR 的行
awk '{c[$7]++} END {for (k in c) print k, c[k]}' access.log   # 数组计数
awk '{s += $8} END {print s}'          # 求和
```

### 实测：多列输出

```console
$ awk '{print $2, $7}' access.log | head -4
10:00:01 200
10:00:03 500
10:00:05 200
10:00:07 500
```

### 数组计数代替 sort | uniq

```console
$ awk '{c[$7]++} END {for (k in c) printf "  状态 %s: %d\n", k, c[k]}' access.log
  状态 200: 4
  状态 404: 1
  状态 500: 5
```

**这比 Phase 1 的 `sort | uniq -c` 更快**（不启动外部进程、不产生管道），因为 sort 必须等所有输入排完才能输出，awk 一次遍历搞定。

⚠️ **`for (k in c)` 的遍历顺序是不确定的**，需要有序输出时得自己排序。

### 条件聚合

```console
$ awk '{gsub(/ms/,"",$8); if ($8+0 > 200) {n++; s+=$8}} END {print "慢请求数:", n, " 合计:", s, "ms"}' access.log
慢请求数: 4  合计: 2130 ms
```

## 4. awk 的字符串陷阱（**本节最值钱**）

这是日志分析里最隐蔽的一类 bug，实测如下。

### 现象：`$8 > 50` 判断失效

```console
$ printf '9ms\n100ms\n' | awk '{ if ($1+0 > 50) print $1, "慢请求 ✓" }'
9ms 慢请求 ✓
100ms 慢请求 ✓          ← 正确

$ printf '9ms\n100ms\n' | awk '{ if ($1 > 50) print $1, "慢请求 ✓" }'
9ms 慢请求 ✓            ← 漏掉了 100ms！
```

**原因：** awk 判断字段是数字还是字符串，看它长得像不像数字。`9ms` 不像纯数字，于是**比较时按字符串字典序**：

- 字符串比较 `"100ms" > "50"` → 比首字符 `'1'` vs `'5'` → false
- 字符串比较 `"9ms" > "50"` → `'9'` vs `'5'` → true

**于是 100ms 被当成"不比 50 大"，静默漏掉了。** 这种 bug 不会报错，只会给出一个看起来合理的错误数字 —— 是最难查的一类。

### 累加时也会中招

```console
$ printf '12ms\n340ms\n' | awk '{a+=$1} END {print a}'
352                                    # 首字符是数字，awk 隐式转换侥幸对了

$ printf 'ms12\n' | awk '{a+=$1} END {print a}'
0                                      # 首字符不是数字 → 0，静默出错
```

### 铁律

**字段带单位/带前缀时，一律先 `gsub` 去单位，再 `+0` 强制转数字。**

```bash
awk '{ gsub(/ms/, "", $8); if ($8 + 0 > 200) ... }'
#                        ^^^^^^ 关键
```

`+0` 的作用是强制把 strnum 转成 number。gawk/mawk 都支持。

## 5. `$0` 是什么

`$0` 代表**整行**。所以：

```bash
awk '{print}'      file   # 等价于 cat
awk '{print $0}'   file   # 同上
```

`print` 不带参数时默认打印 `$0`，这就是 `awk '{print}'` 等价于 `cat` 的原因。

## 6. 批量改文件后缀（题目第 6 题的真相）

### 先说结论：题目里的做法**改不了文件名**

```console
$ echo "hello" > a.log
$ sed -i "s/\.log$/.txt/" a.log
$ cat a.log
hello                                # 文件内容没变
$ ls -1
a.log                                # 文件名也没变
```

**`sed -i` 改的是「文件内容」里的文字，跟文件名是两回事。** 题目里的 `sed 's/\.log$/.txt/'` 试图替换内容中的 `.log` 字样 —— 但日志内容里根本没有这段字符串，所以什么都不会发生。

（思考题问"不加 `-i` 会怎样"，实测答案是：**只把结果打到屏幕，文件完全不动**。这其实是好事，说明 `sed` 默认就是安全的。）

### 正确写法

```bash
for f in *.log; do
    mv "$f" "${f%.log}.txt"
done
```

实测：`a.log b.log c.txt` → `a.txt b.txt c.txt`。

**`${f%.log}` 是 bash 参数展开**：去掉 `f` 结尾的 `.log`。比调 `sed` 拼字符串快得多，也不容易出错。

如果文件名里可能含换行/特殊字符，用 `find -exec`：

```bash
find . -name '*.log' -exec sh -c 'mv "$1" "${1%.log}.txt"' _ {} \;
```

## 思考题答案

### 1. grep 和 sed 都能处理每一行，分工是什么

- `grep` 是**选择器**：只决定哪些行被输出/继续传递，不修改内容
- `sed` 是**编辑器**：逐行应用替换/删除规则，改变内容本身

组合方式：`grep ERROR file | sed 's/500/503/g'` —— 先筛出错误行，再把状态码统一改掉。

### 2. `sed -i` 的风险与安全做法

风险：正则写错会静默批量破坏文件，且没有撤销。

安全做法：
1. 先**不带 `-i`** 跑一遍，检查输出
2. 用 `sed -i.bak` 留备份
3. 重要数据先 `cp` 一份

### 3. `$0` 是什么，为什么 `print` 等价于 `print $0`

`$0` 是整行内容。`print` 无参数时默认打印 `$0`，所以 `awk '{print}'` 就是 `cat`。

### 4. 第 6 题为什么用 `sed -i`

**这里要纠正题目本身的前提**：`sed -i` 改的是文件**内容**，不是文件名。真正的原因是：

- 题目里想用 `sed` 替换内容中的 `.log` 字样，但日志内容里没有，所以无效
- **改文件名只能用 `mv` + 参数展开 `${f%.log}`**
- 循环里不加 `-i` 时 `sed` 只输出不落盘，所以"改了个寂寞"

这题其实是个很好的教学案例：**它暴露了"以为某命令能干什么"和"它实际能干什么"的差距。**

## 本阶段速查

```bash
# grep
grep -i     # 忽略大小写
grep -E     # 正则
grep -c     # 计数
grep -o     # 只输出匹配部分
grep -v     # 反选
grep -rn    # 递归带行号
grep -A2 -B2 -C2   # 上下文行数

# sed
sed 's/a/b/g'         # 替换
sed -i                # 原地修改
sed -i.bak            # 原地修改 + 备份
sed '/pat/d'          # 删匹配行
sed -n '5,8p'         # 只打印 5-8 行

# awk
awk '{print $N}'      # 第 N 列
awk -F','             # 自定义分隔符
awk '/pat/{...}'      # 条件处理
awk '{a[$1]++} END{}' # 数组计数
awk '{s+=$1} END{print s}'  # 求和
awk 'BEGIN{}' / END{}  # 开始 / 结束块
$0  # 整行
$1+0 # 强制转数字
```
